# The V5 quality verdict, and the process correction behind it

**Ruled by the product owner on the rendered screenshots, 20 August 2026.**

| | |
| --- | --- |
| Economic integrity | **Strong** |
| System / test discipline | **Strong** |
| Causal model | **Strong** |
| Visual composition | **Insufficient** |
| World immersion | **Insufficient** |
| Interaction presentation | **Insufficient** |
| Consumer-product quality | **Insufficient** |

The finding, in one sentence: **the economics have become more real than the interface.** That
is a better problem than fake polish, and it is still a problem.

## What the screens actually are

Highly styled interactive documentation. The service phase runs a real evening off a real
engine and renders it as a large title, an explanatory paragraph, three status boxes, a warning
bar and a button. *The actual business is visually absent.* A screen whose model is alive
cannot look static.

Named failures, to be checked against on every future surface:

- The dominant object is the headline. That is backwards. `THE WINDOW IS OPEN` set at display
  size is the product explaining a state the environment should simply make obvious.
- Full-width bands, equal-weight rectangular panels, oversized headings, dark surfaces separated
  mainly by borders. **Dark mode is not premium design.**
- Explaining the system in prose where interaction could make it understood. Three cards
  defining stock, cushion and cut — every run, before anything can be touched.
- The world HUD reads as a developer status strip rather than as instrumentation belonging to a
  night market.

## The process correction, which matters more

The Gauntlet was commissioned as *"OPUS 5 ORCHESTRATED / MULTI-AGENT / WORKFLOW-DRIVEN"* and had
drifted into one model writing first drafts and occasionally asking an agent for review. That
defeats the point: a surface designed by one brain and reviewed afterwards is a surface with one
brain's blind spots, and the visual gap above is exactly the shape of that failure.

Standing rules from here:

1. **Every major surface gets at least three genuinely different product architectures before
   anything is committed** — different information and interaction models, not different corner
   radii. Designers work blind to each other.
2. **Courts judge separately and are not asked to agree**: product, interaction, visual,
   evidence, accessibility, red team. Unanimous immediate agreement is treated as a warning.
3. **Screenshots are the design artifact.** A court that reviews JSX cannot see that a screen
   looks like documentation. Every visual judgement is made against rendered output.
4. **Opus frames, dispatches, inspects and rules.** It implements when that is genuinely the
   best use of the turn, not by default.
5. **Checkpoints report which workflows actually ran and what they changed.** No agent theatre —
   only consequential workflows are worth naming.

The precedent for all of this is already in the repository: in the supplier war, one judge scored
a design 3.5 and another scored the same design 8.0, and reconciling that disagreement surfaced a
dominant-strategy defect that neither judge had been looking for. Disagreement found the bug.

## What is not up for renegotiation

The visual criticism must not be answered by inventing economy. No menu, no per-item prices, no
reputation, no weather, no tips, no dynamic pricing. The world has one good — a plate, $12, ten
to a tray — and every figure in `economy.ts`, every verdict in `resolution.ts` and all 174,339
states of the balance sweep rest on it. If richer mechanics turn out to be necessary for the
experience, that is a separate economic design war with its own cost stated up front.
