the exact failure the canary exists to prevent, arriving through the one door it does not

--force converts and says plainly what it is leaving behind and that the new key will not
open it, because forcing does not repair those records — it only records that somebody meant
it.

================================================================================
The rule, and why it is not "refuse a non-empty --to"
================================================================================

The check is: every `.json` in --to must be a path the source also holds (the canary is
excluded — this run rewrites it last anyway).

"Refuse any non-empty destination" would have cost property 6. A resumed run's destination is
full of records: all of them written by the run that crashed, all of them paths in the source.
Under this rule that is not a stranger and resume still works —

  $ rm dst2/C00007/class.json
  $ BOW_OLD_STORE_KEY=… BOW_NEW_STORE_KEY=… node .../rekey.js --from src --to dst2
  1 converted, 5999 already done.
  exit=0

— while a foreign record, which by definition is not a path the source holds, is caught.
A destination record that *is* in the source but was sealed with some other key is still
overwritten from the source, exactly as vendor receipt 04 verified; that is a correct
conversion, not a stranger.
