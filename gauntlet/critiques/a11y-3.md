# Accessibility critique — a11y-3

**Question:** can every student in a class use this?
**Bar:** WCAG 2.2 AA, verified in a real browser rather than asserted, plus the harder question a
standard cannot ask — *is what a blind or keyboard-only student hears enough to do the task, or
only enough to know something happened?*

**Under test:** commit `8685d0b`, exported to a clean directory and served from there, so nothing
another agent edited mid-audit could move under a measurement.
**Where:** app on `http://127.0.0.1:5410` (Vite), class service on `http://127.0.0.1:5480`
(`BOW_CLASS_STORE=memory`, so nothing here touched another agent's classes).
**Browser:** Chromium 1194 at `/opt/pw-browsers/chromium`, driven by Playwright 1.62.1 with
`executablePath` pinned — nothing was installed. axe-core **4.13.0** from `node_modules`.
**Receipts:** `gauntlet/receipts/a11y-3/`. Every line quoted below is in one of those files.

*(This file is written and committed as the evidence lands, per the standing instruction to
commit incrementally. Sections marked **[in flight]** are still being measured.)*

## What is done well, and it is not a small list

A critique that opened with the defects would be a dishonest description of this product. Four
things here are better than most commercial ed-tech I have driven:

1. **axe is silent.** 26 distinct Basketball screens scanned against `wcag2a wcag2aa wcag21a
   wcag21aa wcag22aa`: **zero violations, zero failing nodes.** Not "no criticals" — none at all.
   `gauntlet/receipts/a11y-3/axe/basketball.json`.
2. **Focus is managed on arrival at almost every screen.** Twenty-one screen changes were
   recorded by reading `document.activeElement` rather than guessing, and nineteen of them land
   focus on the new screen's own heading. The world picker — a BLOCKER in the previous
   accessibility recon — now lands on `h1 "Pick a world. Make it count."` The stage heading is a
   real focus target (`tabIndex={-1}`), and stages that change their own question under one stage
   id move focus with `focusKey`. `gauntlet/receipts/a11y-3/keyboard/basketball.log`.
3. **The announcement stream is genuinely informative, not decorative.** The money ledger
   announces every change (`Still to give a job $3,100.` → `$1,900` → `Nothing left to place.`),
   the writing gate announces its own progress in three parts and updates each one as it is met
   (`✓ 2 of Avery's numbers, tapped. ◦ Write each number you tapped into your answer. $5,000 and
   $1,200 are not in it yet. ✓ 2 sentences so far.`), and the delivery states are spoken
   (`Sending it to your class now…`). Fifty-one distinct announcements across one run:
   `gauntlet/receipts/a11y-3/screenreader/basketball-announcements.txt`.
4. **The reading tools cost the student nothing, and that is true on the bytes.** After opening
   the tools, opening the glossary and pressing read-aloud, I dumped every key this device holds:
   `bow.reading.v1` is a device-local preference and the attempt log contains
   `["SESSION_STARTED","STAGE_ENTERED","WORLD_CONFIRMED","STAGE_ENTERED","SETUP_RANKED"]` — no
   reading event of any kind. Grepping the whole of `localStorage` for `READ_ALOUD`, `readAloud`,
   `glossary`, `speech` returns **zero**. `gauntlet/receipts/a11y-3/probes/read-aloud.log`.
5. **The glossary is a correct modal dialog.** `role="dialog" aria-modal="true"`, labelled by its
   own `h2`, focus moves to the heading on open, Tab is trapped inside (fourteen presses, three
   stops, no leak), Escape closes it, and **focus returns to the "Words" button that opened it.**
   `gauntlet/receipts/a11y-3/probes/tools.log`.
6. **Nothing in the student flow is timed.** No countdown, no auto-advance, no session that
   expires inside a lesson: a shared-device student session is 10 hours
   (`SHARED_DEVICE_SESSION_HOURS = 10`), which is longer than a school day. WCAG 2.2.1 is not
   engaged because there is no time limit to extend.

## How to reproduce anything here

```bash
# a clean copy of the commit under test, so nothing moves mid-measurement
SNAP=/tmp/a11y3/snap; mkdir -p $SNAP
git archive 8685d0b | tar -x -C $SNAP
ln -s /home/user/bow-decision-challenges/node_modules $SNAP/node_modules

cd $SNAP
BOW_API_PORT=5480 npx vite build --ssr server/index.ts --outDir dist-server
BOW_API_PORT=5480 BOW_CLASS_STORE=memory \
  BOW_ALLOWED_ORIGIN="http://127.0.0.1:5410,http://localhost:5410,http://127.0.0.1:5480" \
  node dist-server/index.js &                       # class service on :5480
BOW_API_PORT=5480 npx vite --host 127.0.0.1 --port 5410 --strictPort &   # app on :5410
```

The drivers live in the scratch copy at `a11y3/` and are reproduced verbatim in
`gauntlet/receipts/a11y-3/drivers/`. Each one records `document.activeElement` at every step
rather than asserting on it, so the receipts are a transcript rather than a pass/fail.
